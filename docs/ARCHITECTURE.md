# المعمارية

## المبدأ الحاكم

ثلاث حدود لا تُخترق، وكل قرار في الكود يخدمها:

1. **الأمان بوابة واحدة.** كل استدعاء أداة يمرّ عبر `ToolRegistry.invoke` ثم `PermissionBroker`.
   لا يوجد مسار جانبي ينفّذ إجراءً على الجهاز.
2. **القدرات صريحة.** لا أداة تدّعي قدرة لا تملكها. إن كانت إمكانية الوصول معطّلة، تُعيد الأدوات
   رسالة خطأ صريحة بدل نجاح وهمي. إن لم يوجد `adb`، تقول `adb_connect` ذلك.
3. **التعلّم مرئي وقابل للعكس.** كل ما «تعلّمه» الوكيل ملف JSON في `filesDir/agent/` يمكنك
   قراءته وحذفه من الواجهة.

## مسار الطلب

```
المستخدم → AgentViewModel.submit
        → AgentEngine.runInternal   (Mutex: مهمة واحدة، سقف خطوات)
            → PromptBuilder.build   (النظام + القواعد + الذاكرة + الأدوات)
            → LlmClient.chat        (OpenAI-compatible, tools)
            → ToolRegistry.invoke   → PermissionBroker.approve (LOW تلقائي، HIGH يسأل)
                                    → AgentTool.execute
            → ChatMessage.tool      → حلقة جديدة حتى إجابة نهائية أو سقف الخطوات
        ← EventBus (Log / ToolStarted / ToolFinished / ConfirmNeeded / Answer)
        ← الواجهة + log.jsonl
```

## لماذا OpenAI-compatible؟

عميل واحد يعني: مزوّد واحد للصيانة، وحرية تبديل المزوّد بلا كود، ودعم دالة `tools`
القياسية التي تحتاجها حلقة الوكيل. المزوّدون المدعومون: OpenAI، OpenRouter، Groq، DeepSeek،
Mistral، Together، Gemini (compat)، Ollama.

## التطوير الذاتي: ثلاث طبقات

### 1) مهارات (Skills)
خطة = مصفوفة خطوات `{tool, args, save_as}`. عند الحفظ:
- تُتحقَّق كل خطوة ضد السجل الحقيقي؛ أداة غير موجودة ⇒ رفض الحفظ.
- المتغيّرات `{{name}}` تُعوَّض عند التشغيل من `params` أو من مخرجات خطوات سابقة.
- أي خطوة ترجع `ERROR`/`DENIED` توقف التنفيذ وتُبلَّغ بدقة (رقم الخطوة والسبب).

### 2) تعلّم بالقياس
`runs` و`successes` لكل مهارة ⇒ `reliability`. تُعرض في الواجهة، ويقرأها الوكيل من
`list_skills` ليقرّر: يعيد الاستخدام، أو يعدّل، أو يحذف.

### 3) قواعد وذاكرة
`add_rule` تُدرج نصًا في تعليمات النظام لكل مهمة قادمة (تفضيلات ثابتة).
`remember` يخزّن حقائق مفاتيح/قيم تُحقن في الـ prompt.

### ما لا يمكن فعله (بصدق)
تعديل الكود المصدري أو إعادة بناء APK من داخل التطبيق غير ممكن على أندرويد بلا أدوات بناء
وتوقيع. المسار الواقعي: الوكيل يقترح تغييرًا → يُفتح PR → يُبنى إصدار جديد → المستخدم يثبّته.

## طبقة الجهاز

### Accessibility
`AgentAccessibilityService` يقدّم واجهة صغيرة: `describeScreen`, `clickByText`, `clickNodeAt`,
`typeText`, `scroll`, `tap`, `swipe`, وأزرار النظام. الشجرة تُبسَّط إلى JSON (حد 120 عنصرًا)
لتبقى الرموز (tokens) معقولة.

### Intents
الأفضلية دائمًا للأداة المخصّصة ثم الـ Intent (فتح تطبيق، منبه، مؤقت، بريد جاهز) لأنها آمنة
ولا تحتاج إمكانية الوصول.

### Shell
`sh -c` بصلاحيات التطبيق فقط، مع مهلة ونمط حجب. لا root. `adb_connect` صادق في تقرير غياب
الملف التنفيذي.
