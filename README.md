# djb ai — وكيل ذكاء اصطناعي على أندرويد

تطبيق أندرويد أصلي (Kotlin + Jetpack Compose) يعمل كـ **وكيل (agent)** على هاتفك: يفهم طلبك،
يخطّط، ينفّذ على الجهاز بالأدوات، ثم يخبرك بما حدث فعلًا — ويكتب لنفسه **مهارات** يعيد استخدامها.

> **الحالة:** الإصدار `0.1.0` — **APK مبني ومتوفر للتحميل** (debug، غير موقّع للنشر).
> راجع [الحدود الصريحة](#الحدود-الصريحة) قبل التوقّع.

---

## ما يفعله فعليًا

| المجال | القدرة | الأداة |
|---|---|---|
| رؤية الشاشة | قراءة شجرة الواجهة الحالية (نصوص، أزرار، حقول) | `read_screen` |
| التحكم | نقر بالنص/بالفهرس/بالإحداثيات، سحب، كتابة، تمرير، أزرار النظام | `click_text`, `click_index`, `tap`, `swipe`, `write_text`, `scroll`, `system_button` |
| التطبيقات | فتح تطبيق بالاسم أو الحزمة، قائمة التطبيقات المثبّتة | `launch_app`, `list_apps` |
| النظام | رابط، إعدادات، حافظة، اهتزاز، رسالة قصيرة | `open_url`, `open_settings`, `clipboard`, `vibrate`, `toast` |
| التواصل | فتح رسالة/بريد/لوحة اتصال **جاهزة** (الإرسال بلمسة منك) | `compose_sms`, `compose_email`, `dial` |
| الوقت والوسائط | منبه، مؤقت، تحكم تشغيل، مستوى الصوت | `set_alarm`, `set_timer`, `media_control`, `set_volume` |
| shell | أوامر بصلاحيات التطبيق فقط | `run_shell`, `shell_capability` |
| **الرؤية البصرية** | التقط صورة الشاشة وأرسلها للموديل ليرى الأيقونات والتخطيطات التي لا يصفها النص | `look`, `screen_text_only` |
| **ADB حقيقي** | اتصال ADB عبر TCP **داخل التطبيق** (مكتبة `dadb`، بلا ملف adb وبلا كمبيوتر): shell بصلاحيات shell، نقر/سحب/كتابة، أزرار، تشغيل الحزم، أبعاد الشاشة | `adb_connect`, `adb_status`, `adb_shell`, `adb_tap`, `adb_swipe`, `adb_text`, `adb_key`, `adb_launch`, `adb_current_app`, `adb_packages`, `adb_screen_size`, `adb_disconnect` |
| **مهام مجدولة** | جدولة مهام تتكرر (مرة/كل ساعة/يوميًا/أسبوعيًا) وتُنفَّذ في الخلفية بلا فتح التطبيق، مع إعادة تسجيل تلقائي بعد إعادة التشغيل | `schedule_task`, `list_scheduled_tasks`, `cancel_scheduled_task` |
| **التطوير الذاتي** | إنشاء/تعديل/حذف مهارات، قياس موثوقيتها، قواعد دائمة، ذاكرة | `create_skill`, `save_skill`, `run_skill`, `list_skills`, `delete_skill`, `inspect_skill`, `add_rule`, `remember`, `recall` |

## التطوير الذاتي — كيف يتحقق فعلًا

لا يمكن لتطبيق أندرويد أن يعدّل ملف APK الخاص به وهو يعمل، ولا أن يعيد بناء نفسه. لذا
«التطوير الذاتي» هنا مُنفَّذ بثلاث طبقات حقيقية وقابلة للفحص:

1. **مهارات يكتبها بنفسه.** المهارة خطة JSON من خطوات أدوات موجودة. يكتبها الوكيل عبر
   `create_skill`، وتُتحقَّق كل خطوة قبل الحفظ (لا أدوات وهمية)، وتُخزَّن في `filesDir/agent/skills.json`.
2. **مقاييس تعلّم.** كل تشغيل يسجّل `runs` و`successes`؛ الموثوقية تُحسب وتُعرض في الواجهة،
   فيميل الوكيل للمهارات التي تنجح ويعدّل التي تفشل (`inspect_skill` ثم `create_skill` من جديد).
3. **قواعد وذاكرة دائمة.** `add_rule` تُدرج القاعدة في تعليمات النظام لكل مهمة قادمة،
   و`remember` يبني حقائق ثابتة عنك وعن جهازك.

الطبقة التي **ليست** هنا، بصدق: توليد كود جديد أو تعديل الكود المصدري ذاتيًا. ذلك يحتاج
إصدارًا جديدًا (انظر خارطة الطريق في `docs/ARCHITECTURE.md`).

## التوجيه الذكي بين موديلين

كل مهمة تمر بمرحلتين، ويمكن أن يخدمهما موديلان مختلفان:

| المرحلة | ماذا تشمل | الأداة الاقتصادية |
|---|---|---|
| **تخطيط** (أول قرار) | فهم الطلب وتحديد أول خطوة — برومبت قصير | موديل صغير/سريع |
| **تنفيذ** (بقية الخطوات) | استدعاء الأدوات مع سجل طويل ومخططات 43 أداة | الموديل الأساسي |

في تبويب **المزوّدون** لكل مزوّد زرّان: **الدور** (`تخطيط` / `تنفيذ` / `عام`) و**موديل التخطيط**
(اختياري). سلسلة التبديل التلقائي تبقى شبكة أمان: `المزوّد المفضّل للدور → مزوّدون عامّون → البقية`،
فلا يصبح التوجيه نقطة فشل واحدة. سطر «التوجيه الحالي» في أعلى الشاشة يوضّح من سيخدم كل مرحلة الآن.

## أفضل ما في العالمين: ذاكرة تتراكم + تدريب يشبه LLM

التطبيق لا يستطيع تدريب أوزان على الهاتف — لكنه يملك ما لا يملكه أحد: **تجربتك الموثّقة**.
لذلك بُني الجسر في اتجاهين:

| الاتجاه | الآلية | الأثر |
|---|---|---|
| **فوري (محلي)** | `learn_lesson` يستخلص درسًا واحدًا من آخر مهمة **نجحت**، ويُحقن في كل تخطيط قادم | تحسّن فوري بلا تكلفة تدريب |
| **عميق (عند المزوّد)** | `export_training` يُخرج JSONL بصيغة OpenAI (system/user/assistant) من التشغيلات الناجحة | تجربتك تتحوّل إلى **أوزان** على مزوّدك بمفتاحك |

**لماذا هذا هو «الأفضل منهما»:** التدريب على LLM يمنح **التعميم**، والتطبيق يمنح **الخصوصية
والأثر**. الدمج يعطيك موديلًا تعلّم *هاتفك وتطبيقاتك وعاداتك* من عمل حقيقي ناجح — لا من نصوص مسحوبة.

**حدود صريحة:** لا نُصدّر إلا التشغيلات الناجحة (التدريب على الفشل يُعلّم الخطأ)، والملف بصيغة
خطة-نصية لا tool-calls، لأن صيغة نداء الأدوات تختلف بين المزوّدين وتخمينها يُدرّب شيئًا خاطئًا.

## النمو والاستقلالية

الاستقلالية **مكتسبة لا ممنوحة**. حلقة من أربع مراحل تعمل على سجلّ الوكيل الحقيقي:

| المرحلة | ما يحدث |
|---|---|
| **تقييم** | موثوقية كل مهارة من تشغيلاتها الفعلية (3 تشغيلات على الأقل قبل أي حكم) |
| **إصلاح** | المهارة الفاشلة تُعاد كتابتها بالموديل، **تُفحص في الحاوية المغلقة**، ولا تحلّ محل الأصلية إلا إن اجتازت. حد أقصى إصلاحان |
| **تقليم** | ما تجاوز حد الإصلاحات يُتقاعد (لا يُحذف) — فيبقى السجل والتاريخ |
| **ترقية** | الاستقلالية ترتفع درجة واحدة عند **20 تشغيلًا بنجاح 80%+**، وتنخفض فورًا عند سجل أقل من 50% |

المهم: **لا يمكن قفز مستوى**. `ASK ← BALANCED ← FULL` درجة واحدة في كل مرة، والأدلة من
عمل الوكيل نفسه لا من رأيه في نفسه. لهذا «استقلاله» نتيجة سجل، لا زرّ يضغطه.

## الحاوية المغلقة وصمّام الأمان

أي تعديل على الوكيل نفسه يمر بثلاثة أبواب، ولا يُحقَن شيء قبل اجتيازها:

**1. حاوية مغلقة (8 فحوص، بلا موديل وبلا شبكة):**

| الفحص | ما يمنعه |
|---|---|
| PARSE | أقواس/تنصيص مختل، تعليق مفتوح سيبتلع بقية الملف |
| LINK | إشارة إلى أداة غير مسجّلة (تفشل وقت التشغيل فقط) |
| INTEGRITY | بصمة SHA-256 لما تم فحصه بالضبط — يكشف أي تبديل بعد الفحص |
| SAFETY | حذف حراسة صلاحيات أو إضافة وصول جذر |
| SCHEMA | `enum` بلا `type` — سبب خطأ 400 الذي وقعنا فيه سابقًا |
| REGISTRY | أسماء مكرّرة أو عدد أدوات غير منطقي |
| SMOKE | تعذّر وصف الأدوات الذاتي، أو وصف يزيد عن 2000 حرف |
| INVARIANTS | اختلال افتراضي الصلاحيات |

**2. ترقية مشروطة (A/B):** قبل أي ترقية تُحفظ **نسخة مستقرة كاملة** (مهارات + قواعد + ذاكرة + إعدادات).
النسخة الجديدة تُسجَّل كمرشّحة، والمستقرة تبقى سليمة.

**3. صمّام أمان:**
- زر أحمر دائم في «النسخ والصمّام» ← استعادة فورية.
- **تراجع تلقائي**: فحص سلامة عند كل إقلاع (ملفات تالفة، مهارات تشير لأدوات محذوفة، كل المزوّدين معطّلون)؛
  فشلان متتاليان بعد ترقية ← تعود النسخة المستقرة بلا أن تفعل شيئًا.
- الاستعادة تعيد الحالة **كما كانت**، فتزيل ما أُضيف بعدها لا تدمج فقط.

## تعلّم من تكراره + تعديل كوده

**أ) اكتشاف الأنماط.** محرّك يقرأ سجل التدقيق ويجد نفس تسلسل الأدوات (3 خطوات أو أكثر) متكررًا
في **مهام مختلفة** — لا يخلط التكرار داخل مهمة واحدة بالعادة. يعرض الاقتراح مع عدد التكرار،
وبضغطة واحدة يتحوّل إلى مهارة حقيقية بقيم معمّمة (`{{text}}`, `{{x}}`) لا مسجّلة.

**ب) رقع على كوده.** التطبيق يقرأ **مصدره الحقيقي** (لقطة تُبنى في كل بناء) ويقترح `diff` موحدًا:

| الأداة | العمل |
|---|---|
| `source_list` / `source_read` / `source_search` | قراءة الكود الحقيقي — لا تخمين |
| `self_patch` | يقترح `find`/`replace` ويُنتج diffًا؛ يُرفض إن كان النص غامضًا أو كسر توازن الأقواس |
| `self_patches` | الرقع السابقة وأسبابها |

**الحد الصريح:** التطبيق لا يعدّل نفسه وهو يعمل — الكود مُصرَّف داخل APK. ما يفعله هو قراءة مصدره،
إيجاد الخلل، واقتراح تعديل دقيق **تراجعه أنت** ثم يُطبَّق ويُبنى APK جديد. كل رقعة قابلة للتصدير
والرفض، والفحص يمنع أي رقعة تُفسد الملف.

## النسخ الاحتياطي (تصدير/استيراد)

كل ما تعلّمه التطبيق — المهارات، الذاكرة، القواعد، المهام، سلسلة المزوّدين، الإعدادات — في ملف
JSON واحد من الإعدادات ← «النسخ الاحتياطي».

- **المفاتيح اختيارية**: التصدير الافتراضي بلا مفاتيح API، آمن للمشاركة. أدرجها فقط إن كنت تحتفظ بالملف لنفسك.
- **الاستيراد دمج لا استبدال**: مهارة بنفس الاسم تُحدَّث، والجديدة تُضاف، والذاكرة تندمج — لا يُحذف شيء.
- **مفتاح ADB الخاص لا يُصدَّر أبدًا** — أعد الإقران على الجهاز الجديد.
- الاختيار عبر منتقي ملفات النظام (SAF)، فلا حاجة لأذونات تخزين.

## المهارات الشرطية

المهارة ليست خطوات متتالية فقط — كل خطوة تتحكم في مصيرها:

| الحقل | المعنى |
|---|---|
| `retry` | 0-3 محاولات إضافية عند الفشل (شبكة، واجهة لم تُحمّل بعد) |
| `stop_on_error` | `false` يعني خطوة تجميلية لا تُسقط الخطة |
| `branches` | `[{"when":"نص","match":"contains"/"not_contains","then":[…]}]` — تُقيَّم على **نتيجة الخطوة**، وهي طريقة التعافي داخل خطة محفوظة |

مثال حقيقي: اقرأ الشاشة، وإن لم تُوجد كلمة «إرسال» اذهب عبر الإعدادات. الوكيل يكتب هذا بنفسه
عبر `create_skill`، والواجهة تُظهر عدد الخطوات الشرطية وموثوقية كل مهارة من التشغيل الفعلي.

## الرؤية البصرية

الوكيل يستطيع **النظر** لا القراءة فقط: أداة `look` تلتقط الشاشة وترسلها للموديل كرسالة
متعددة الوسائط (نص + صورة base64)، فيرى الأزرار الأيقونية والصور والواجهات المرسومة (Canvas).

مساران للالتقاط، أيهما متاح:
1. `takeScreenshot` من خدمة إمكانية الوصول (أندرويد 11+) — بلا إقران.
2. `screencap` عبر ADB — يعمل إن كانت الخدمة معطّلة لكن ADB مقترن.

**مهم:** يجب أن يكون الموديل بصريًا (‏`gpt-4o`، `gemini-2.x`، `claude`، `qwen-vl`). مع موديل نصي
سيرفض المزوّد الطلب. يمكن تعطيل الرؤية من الإعدادات (توفيرًا للم tokens).

## ADB اللاسلكي — تحكم أعمق من إمكانية الوصول

التطبيق يتحدث بروتوكول ADB مباشرة (`dev.mobile:dadb`)، فلا يحتاج ملف `adb` تنفيذيًا ولا حاسوبًا:

| ما يتيحه | لماذا يهم |
|---|---|
| نقر/سحب/كتابة/أزرار عبر `input` | يعمل حتى مع تطبيقات **تمنع** خدمات إمكانية الوصول |
| `adb_shell` بصلاحيات shell | قراءة `dumpsys`، إدارة الحزم، ملفات `/sdcard` |
| `adb_current_app` | معرفة التطبيق في المقدمة بلا خدمة شاشة |
| `adb_packages` | جرد التطبيقات ونسخ الاحتياط/الحذف |

**خطوات التفعيل (مرة واحدة):** خيارات المطوّر ← «التصحيح اللاسلكي» ← «إقران الجهاز برمز» ←
ثم أدخل منفذ الاتصال في تبويب ADB ← اسمح لبصمة مفتاح التطبيق في نافذة الإذن.

**حدود صريحة:** الإقران يحتاج لمسة يدوية (أندرويد يمنع التطبيقات من فعله برمجيًا)، لا root،
`input text` لا يدعم العربية على معظم الأجهزة (استخدم الكتابة عبر إمكانية الوصول للعربية)،
والاتصال يتوقف بعد إعادة تشغيل الهاتف.

## المهام المجدولة (العمل في الخلفية)

تبويب **المهام** يتيح جدولة أي طلب ليتكرر تلقائيًا، ويعيد التطبيق تسجيله بعد إعادة تشغيل
الجهاز (`BootReceiver` + `WorkManager` + عامل فحص كل 15 دقيقة كشبكة أمان).

القيود المعلنة بصدق:

- أندرويد يفرض **حدًا أدنى 15 دقيقة** للتكرار الدوري؛ ما دونه غير ممكن دون خدمة أمامية دائمة.
- المهمة تعمل **بلا واجهة**، لذا أي أداة `HIGH` (نقر، كتابة، إرسال) ستُرفض لأن لا أحد يوافق.
  المهام الخلفية المفيدة هي: قراءة معلومات، تذكيرات، ملخصات، رفع تقارير.
- عند تعطّل المهمة (مثلًا لا شبكة) تُسجَّل النتيجة وتظهر في التطبيق، ويمكن ضبط `retry_once`.

## المزوّدون والتبديل التلقائي

التطبيق يدعم **سلسلة مزوّدين** لا مزوّدًا واحدًا. تضيف مفاتيحك الخاصة من الطبقات المجانية
الرسمية (Groq، Google Gemini، Cerebras، OpenRouter، Mistral، NVIDIA NIM، GitHub Models…)
والطلب يتنقّل بينها تلقائيًا:

- عند `429` (تجاوز الحد) أو `5xx` (عطل مؤقت) → ينتقل للمزوّد التالي فورًا.
- عند `401/403` (مفتاح غير صالح) → يسجّل السبب ويعطّل ذلك المزوّد من المحاولات القادمة.
- ترتيب السلسلة تتحكم فيه بالأسهم (أعلى/أسفل)، وزر **اختبار** يجرب كل مزوّد على حدة.
- كل مفتاح يُخزَّن منفصلًا في `filesDir/agent/providers.json`، **ولا يُكتب في السجل ولا يُعرض**.

النتيجة: عدة حصص مجانية صغيرة تتحول إلى ميزانية استخدام واحدة قابلة للاستمرار — بمفاتيحك أنت.

> **تحذير مهم:** لا تستخدم مستودعات «مفاتيح API مجانية» التي تنشر مفاتيح مسرّبة أو مسروقة.
> تلك المفاتيح تُبطَل سريعًا، ومخالفة لشروط المزوّدين، وبعضها وسيط يقرأ طلباتك. القوائم المفيدة
> مثل `cheahjs/free-llm-api-resources` توثّق **أين تُنشئ مفتاحك مجانًا** — وهذا ما نعتمد عليه.

4. «فتح إعدادات إمكانية الوصول» ← فعّل الخدمة.

> هذا **build للتطوير (debug)**: يعمل ويعطيك كل الميزات، لكنه موقّع بمفتاح تطوير ولن
> يقبل تحديثات فوق نسخة release لاحقًا إلا بإزالة التثبيت أولًا. للاستخدام الشخصي هذا كافٍ.

### عبر GitHub Actions (لبناء نسخة جديدة)
ادفع إلى الفرع أو شغّل يدويًا: **Actions → build-apk → Run workflow**، وسيُنشر الـ APK
تلقائيًا في الإصدار `djb-ai-debug`.

### محليًا
```bash
# يحتاج JDK 17 + Android SDK 35
gradle wrapper --gradle-version 8.9   # مرة واحدة: المستودع لا يحمل gradle-wrapper.jar
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## التشغيل الأول

1. افتح التطبيق ← **الإعدادات** ← اختر مزوّدًا (أو اكتب Base URL) ← ضع مفتاح API ← اسم الموديل ← **حفظ الاتصال**.
2. **فتح إعدادات إمكانية الوصول** ← فعّل `djb ai` ← اسمح.
3. اضبط **درجة الاستقلالية**: `اسألني` (الافتراضي، الأأمن) / `متوازن` / `كامل`.
4. جرّب: «افتح الإعدادات وأخبرني نسبة البطارية»، ثم «احفظ ما فعلته كمهارة اسمها فحص_الجهاز».

## الأمان والصلاحيات

- كل أداة تحمل درجة خطورة (`LOW` / `MEDIUM` / `HIGH`)، و`PermissionBroker` هو البوابة الوحيدة:
  في وضع «اسألني» لا تُنفَّذ أي عملية `HIGH` (نقر، كتابة، رسالة، shell) دون موافقتك.
- سجل تدقيق (`log.jsonl`) لكل استدعاء أداة ونتيجته، معروض في تبويب **السجل**.
- أنماط خطرة محظورة داخل `run_shell` (مثل `rm -rf /` أو تعطيل خدمة إمكانية الوصول).
- لا تُرسل بيانات لجهة غير مزوّد الموديل الذي اخترته. لا تحليل ولا تتبّع.

## الحدود الصريحة

- **لا root، ولا تحكم كامل بالجهاز.** التنفيذ بصلاحيات التطبيق. `adb_connect` يعمل فقط إن
  وُجد ملف `adb` تنفيذي وأعدّ المستخدم الاقتران اللاسلكي — التطبيق يخبرك بذلك ولا يزيّف نجاحًا.
- **بعض المفاتيح لا تُقلَب برمجيًا** على أندرويد 13+ (واي فاي/بلوتوث): تُفتح صفحة الإعدادات.
- **الكتابة في تطبيقات أخرى** تتم عبر إمكانية الوصول، وقد ترفضها بعض التطبيقات المحمية.
- **لا إرسال تلقائي** لرسالة أو بريد؛ التطبيق يجهّز المحتوى وأنت تضغط إرسال.
- **لا تعديل للكود الذاتي** كما شُرح أعلاه.
